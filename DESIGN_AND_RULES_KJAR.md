# KJÁR - Дизайн, стиль и правила проекта (Next.js + Express.js + Drizzle + Docker)

Документ описывает визуальный стиль, UX-правила и инженерные соглашения для проекта **KJÁR** (“Глубже только тишь”): энциклопедия (лор), персонажи, посты/новости, ивенты, обсуждения, роли и редакторский контур.

---

## 1) Концепция и настроение

**Визуальная метафора:** карта из колоды, лежащая на столе в северном лесу.
Туман, кора, кованое железо, тканый узор (нотка «Калевалы») — и всё это как оформление
**игровой карты**: рамка, угловые скобы, руна-масть, поле портрета, строка характеристик.

**Принцип:** мрачно и атмосферно, но читаемо. Декора почти нет: работают
форма карты, воздух и один акцент.

### 1.1. Три главные цели дизайна
1. **Чтение и поиск**: лор — главный контент; удобно искать, фильтровать, читать длинные тексты.
2. **Колода**: персонажи, ивенты, обсуждения — карточки с понятной иерархией и статусами.
3. **Редактирование без боли**: редакторы обновляют контент через админку без разработчика.

### 1.2. Запреты
- **Нет** надзаголовочных подписей капсом («eyebrow») и капса с большим трекингом в интерфейсе.
  Исключение — вордмарк `KJÁR`.
- **Нет** рун в основном тексте и в навигации: руна — только декор (масть карты, заглушка изображения).
- Один основной акцент на экран; вторичный — точечно, для статусов.

## 2) Дизайн-система

Токены, шкалы и сигнатурный приём вынесены в отдельный файл **`DESIGN.md`** в корне
проекта. Он источник правды: шесть цветов, две гарнитуры, шкала кегля 13/16/20/28/44/72,
отступы 4/8/16/32/64/128, радиусы 0/4/10. Значение вне этого списка считается багом.

Реализация — `apps/web/app/globals.css`, где в `:root` объявлены ровно те же токены.

Проверка на признаки генерации: `./scripts/slop-check.sh` (правила из `anti-ai-slop.md`).
Скрипт ловит стоп-слова, эмодзи в вёрстке, градиенты, тени, дефолтные гарнитуры и
значения мимо шкалы.

## 3) UX-правила и доступность

### 3.1. Навигация
- Меню: Главная / Энциклопедия / Персонажи / Посты / Ивенты / Обсуждения / Контакты
- На мобиле - drawer меню.
- Хлебные крошки: Лор → Раздел → Статья

### 3.2. Поиск
- Страница `/search`: один запрос идёт параллельно в статьи, персонажей, посты, ивенты и темы.
- Вход — иконка в шапке; на самой странице есть поле и селект «где искать».
- Результаты сгруппированы по типу: заголовок + краткое описание + метка (эпоха, роль, дата, раздел).
- Запрос короче двух символов не отправляется.

### 3.3. Читаемость статей
- Оглавление (якоря) - опционально.
- Фактбокс справа.
- Конец статьи: связанные материалы + обсуждение (если включено).

### 3.4. Доступность
- Контраст AA.
- Видимый focus state.
- Кликабельные зоны ≥ 40px.
- Alt-тексты для значимых изображений.

### 3.5. Responsive
- 3 брейкпойнта: mobile / tablet / desktop.
- На мобиле: фильтры - сверху, затем список.

## 4) Данные и сущности (модель продукта)

### 4.1. Сущности
- **Article**: категория, теги, эпоха, статус, `content` (Markdown/MDX), `summary`, `facts` (JSON).
- **Character**: имя, вид, статус, роль (игрок/НПС), теги, описание, `stats` (JSON), `relations`.
- **Post**: заголовок, summary, content, дата, теги.
- **Event**: дата, статус, описание, участники, ссылки на темы.
- **Thread/Discussion**: тема, сообщения, теги, updatedAt.
- **User**: email/username, `password_hash`, роль, профиль.

### 4.2. Роли и права
- `guest`: чтение публичного
- `user`: профиль, персонажи, участие в обсуждениях/ивентах
- `mod`: модерация + правки (по разрешению)
- `admin`: полный доступ, таксономия

## 5) Стек и архитектура

### 5.1. Технологии
- **Frontend:** Next.js (App Router), TypeScript
- **Backend:** Express.js (REST API)
- **DB:** PostgreSQL + **Drizzle ORM**
- **Password:** bcrypt
- **Docker:** запуск dev окружения скриптом `run-dev.sh`

### 5.2. Структура репозитория (monorepo)
```
/apps
  /web        # Next.js
  /api        # Express.js
/packages
  /db         # Drizzle schema/migrations/shared types
  /ui         # shared UI components (опционально)
/docker
  docker-compose.dev.yml
run-dev.sh
```

### 5.3. Контракты API
- Версия API: `/api/v1`
- Единый формат ошибок:
  - `{"error": {"code":"...", "message":"...", "details": {...}}}`

### 5.4. Next.js соглашения
- Роуты:
  - `/` (home)
  - `/lore`, `/lore/[slug]`
  - `/characters`, `/characters/[id]`
  - `/posts`, `/events`, `/discussions`, `/contacts`
- Компоненты: `components/ui/*`, `components/layout/*`
- Дизайн-токены в одном месте (CSS vars или Tailwind tokens).

### 5.5. Express.js соглашения
- `routes/`, `controllers/`, `services/`, `db/`, `middlewares/`.
- Валидация входа: zod/joi (рекомендуется).
- Auth/roles - middleware.

## 6) Пароли и безопасность (bcrypt)

### 6.1. Хеширование
- Хранить **только bcrypt hash**.
- `bcrypt.hash(password, saltRounds)`  
- Проверка: `bcrypt.compare(password, hash)`

### 6.2. Сессии/токены (выберите один подход)
- JWT (access+refresh, refresh в httpOnly cookie)
- Сессии (express-session + Redis/Postgres)

**Минимум:**
- httpOnly cookie
- SameSite=Lax/Strict
- CSRF защита (если cookie-сессии)

## 7) Drizzle (БД и миграции)

### 7.1. Пример таблиц
- `users`: id, email/username, password_hash, role, created_at
- `articles`: id, slug, title, summary, content_md, category_id, era, facts_json, status, updated_at
- `tags`, `article_tags` (m2m)
- `characters`: id, name, species, status, summary, stats_json, relations_json, created_by
- `posts`, `events`, `threads`, `messages`

### 7.2. Миграции
- Все изменения через миграции Drizzle.
- В dev можно автоприменять миграции при старте API контейнера (опционально).

## 8) Docker и запуск dev через run-dev.sh

### 8.1. Dev окружение
`docker compose` поднимает:
- `db` (Postgres)
- `api` (Express) - dev + hot reload
- `web` (Next) - dev

### 8.2. run-dev.sh (ожидаемая логика)
1) Проверить `.env` / создать `.env.example` при отсутствии.
2) `docker compose -f docker/docker-compose.dev.yml up --build`
3) (Опционально) миграции Drizzle.

### 8.3. Переменные окружения
**DB**
- `POSTGRES_USER`, `POSTGRES_PASSWORD`, `POSTGRES_DB`
- `DATABASE_URL=postgres://...`

**API**
- `PORT=3001`
- `BCRYPT_SALT_ROUNDS=12`
- `JWT_SECRET=...` (если JWT)
- `CORS_ORIGIN=http://localhost:3000`

**WEB**
- `NEXT_PUBLIC_API_BASE=http://localhost:3001/api/v1`

## 9) Правила контента и редакторский контур

### 9.1. Статьи (Markdown/MDX)
Обязательные поля:
- заголовок
- краткое описание (1–2 предложения)
- категория
- эпоха (или “Любая”)
- теги (до 10)
- факты (key-value)

### 9.2. Связи контента
- Статья ↔ персонажи ↔ ивенты ↔ обсуждения  
  (в UI показывать “связанные материалы”, не перегружать)

## 10) Definition of Done (качество)

**UI**
- адаптивность
- loading/empty/error states
- клавиатурная навигация + focus
- проверенный контраст

**Backend**
- валидация входа
- единый формат ошибок
- bcrypt для паролей
- роли через middleware

**DB**
- миграции воспроизводимы
- индексы на `slug`, `created_at/updated_at`, FK

**Docker**
- `run-dev.sh` запускает проект одной командой
- окружение поднимается “с нуля”
