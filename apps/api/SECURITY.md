# Безопасность API

## Реализованные меры безопасности

### 1. Аутентификация (JWT)

**Реализация:**
- JWT токены для аутентификации пользователей
- Токены передаются в заголовке `Authorization: Bearer <token>`
- Токены содержат: `userId`, `email`, `role`
- Время жизни токена: 7 дней (настраивается через `JWT_EXPIRES_IN`)

**Эндпоинты:**
- `POST /api/v1/auth/register` - регистрация нового пользователя
- `POST /api/v1/auth/login` - вход в систему

**Middleware:**
- `authenticate` - обязательная аутентификация
- `optionalAuth` - опциональная аутентификация (для проверки прав на draft контент)

### 2. Авторизация (Роли)

**Роли пользователей:**
- `guest` - чтение публичного контента (0)
- `user` - профиль, персонажи, участие в обсуждениях/ивентах (1)
- `mod` - модерация + правки (2)
- `admin` - полный доступ, таксономия (3)

**Middleware:**
- `requireRole(...roles)` - требует одну из указанных ролей
- `requireMinRole(role)` - требует минимальный уровень роли

**Защита данных:**
- Draft статьи доступны только для `mod` и `admin`
- Публичные эндпоинты доступны всем, но с ограничениями по статусу контента

### 3. Валидация входных данных (Zod)

**Реализация:**
- Все входные данные валидируются через Zod схемы
- Валидация параметров запроса (`validateQuery`)
- Валидация тела запроса (`validateBody`)
- Валидация параметров пути (`validateParams`)

**Примеры:**
- Email должен быть валидным email
- Пароль минимум 8 символов
- Limit/offset валидируются как числа с ограничениями
- Slug валидируется по длине и формату

### 4. Rate Limiting

**Реализация:**
- Лимит: 100 запросов за 15 минут
- Идентификация по IP адресу или User ID
- Автоматическая очистка старых записей

**Настройка:**
- `MAX_REQUESTS` - максимальное количество запросов (по умолчанию 100)
- `WINDOW_MS` - окно времени в миллисекундах (по умолчанию 15 минут)

**Примечание:** В продакшене рекомендуется использовать Redis для распределенного rate limiting

### 5. Хеширование паролей (bcrypt)

**Реализация:**
- Пароли хешируются с помощью bcrypt
- Salt rounds: 12 (настраивается через `BCRYPT_SALT_ROUNDS`)
- Пароли никогда не возвращаются в ответах API

### 6. Защита от SQL-инъекций

**Реализация:**
- Использование Drizzle ORM с параметризованными запросами
- Все пользовательские данные передаются через ORM методы
- Прямые SQL запросы используют `sql` template с параметрами

### 7. Безопасность HTTP заголовков

**Реализованные заголовки:**
- `X-Content-Type-Options: nosniff` - защита от MIME-sniffing
- `X-Frame-Options: DENY` - защита от clickjacking
- `X-XSS-Protection: 1; mode=block` - базовая защита от XSS

### 8. CORS настройки

**Реализация:**
- Ограничение по origin (настраивается через `CORS_ORIGIN`)
- Разрешенные методы: GET, POST, PUT, DELETE, PATCH, OPTIONS
- Разрешенные заголовки: Content-Type, Authorization
- Credentials: включены для cookie-based аутентификации

### 9. Ограничение размера запросов

**Реализация:**
- Максимальный размер тела запроса: 10MB
- Применяется к JSON и URL-encoded данным

### 10. Безопасность подключения к БД

**Реализация:**
- SSL подключение в production (если настроено)
- Пул соединений с ограничениями:
  - Максимум 20 соединений
  - Таймаут простоя: 30 секунд
  - Таймаут подключения: 2 секунды

## Переменные окружения

**Обязательные:**
- `DATABASE_URL` - строка подключения к PostgreSQL
- `JWT_SECRET` - секретный ключ для JWT (должен быть длинным и случайным)

**Опциональные:**
- `JWT_EXPIRES_IN` - время жизни JWT токена (по умолчанию "7d")
- `BCRYPT_SALT_ROUNDS` - количество раундов для bcrypt (по умолчанию 12)
- `CORS_ORIGIN` - разрешенный origin для CORS (по умолчанию "http://localhost:3000")
- `PORT` - порт API сервера (по умолчанию 3001)

## Рекомендации для продакшена

1. **Использовать Redis для rate limiting** - для распределенных систем
2. **HTTPS только** - все соединения должны быть зашифрованы
3. **Регулярная ротация JWT_SECRET** - менять секретный ключ периодически
4. **Мониторинг и логирование** - отслеживать подозрительную активность
5. **Регулярные обновления зависимостей** - поддерживать актуальные версии
6. **Использовать helmet.js** - для дополнительных HTTP заголовков безопасности
7. **Валидация на уровне БД** - добавить constraints в схему БД
8. **Аудит доступа** - логировать все действия с правами mod/admin

## Примеры использования

### Регистрация пользователя
```bash
POST /api/v1/auth/register
Content-Type: application/json

{
  "email": "user@example.com",
  "username": "username",
  "password": "securepassword123"
}
```

### Вход в систему
```bash
POST /api/v1/auth/login
Content-Type: application/json

{
  "email": "user@example.com",
  "password": "securepassword123"
}
```

### Защищенный запрос
```bash
GET /api/v1/articles?status=draft
Authorization: Bearer <token>
```

### Запрос с проверкой роли
```bash
GET /api/v1/admin/users
Authorization: Bearer <token>
# Требуется роль: admin
```
