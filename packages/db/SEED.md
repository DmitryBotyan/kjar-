# Seed скрипт для базы данных

## Описание

Скрипт `seed.ts` заполняет базу данных тестовыми данными для проверки всех сущностей проекта.

## Запуск

### Для Docker окружения (рекомендуется):

`pnpm db:migrate:docker` работает нормально — используйте тот же способ для seed:

```bash
# Убедитесь, что контейнеры запущены
pnpm dev

# В другом терминале запустите seed
pnpm db:seed:docker
```

Скрипт запускает seed **внутри контейнера API**, где доступен хост `db`. Перед seed при необходимости выполняется `pnpm install` (чтобы подтянуть зависимости вроде bcryptjs).

### Для локального окружения:

```bash
# Убедитесь, что БД запущена (например, pnpm dev или только db контейнер) и миграции применены
pnpm db:migrate  # или pnpm db:migrate:docker

# Запустите seed
pnpm db:seed
```

При локальном `pnpm db:seed` используется `SEED_LOCALHOST=1`: скрипт подменяет хост `db` на `localhost` в `DATABASE_URL`, если в `.env` указан Docker-вариант (`@db:5432`). При `pnpm db:seed:docker` подмена не выполняется — внутри контейнера хост `db` корректен. Менять `.env` не нужно.

## Связи

Все связи между сущностями создаются:
- Статьи ↔ Теги (через articleTags)
- Персонажи ↔ Теги (через characterTags)
- Посты ↔ Теги (через postTags)
- События ↔ Теги (через eventTags)
- События ↔ Участники (через eventParticipants)
- Обсуждения ↔ Теги (через threadTags)
- Обсуждения ↔ Сообщения (через messages)

## Важно

⚠️ **Внимание:** Скрипт **удаляет все существующие данные** перед заполнением. Используйте только в dev окружении!

## Проверка данных

После запуска seed можно проверить данные:

1. **Через Drizzle Studio:**
   ```bash
   pnpm db:studio
   ```

2. **Через API:**
   ```bash
   # Список персонажей
   curl http://localhost:3001/api/v1/characters
   
   # Список статей
   curl http://localhost:3001/api/v1/articles
   
   # Список событий
   curl http://localhost:3001/api/v1/events
   ```

3. **Через Frontend:**
   - Откройте http://localhost:3000
   - Проверьте страницы: /characters, /lore, /posts, /events, /discussions

## Повторный запуск

Можно запускать seed многократно - скрипт очистит старые данные и создаст новые.
